# prompt-enhancer (한국어판)

대충 쓴 초안을 구체적인 프롬프트로 다시 써 줘요. 프로젝트의 CLAUDE.md, 설치된 스킬, 지금까지의 대화를 참고해요. 다시 쓴 걸 확인한 다음 보내면 돼요.

한국어판 제작: [robinade](https://github.com/robinade) · [mod 모음과 필요 조건](../README.md)

한국어로 쓴 초안은 자연스러운 한국어로 다듬어요. 파일 경로, 코드, 명령어, 스킬 이름은 원문 그대로 둬요. 무엇을 더했는지 알려 주는 메모도 한국어로 나와요.

세션 모델에 맞는 **프롬프트 카드**(그 모델의 공식 프롬프트 가이드를 줄인 것)가 있으면 그것도 반영해요. 가이드를 매번 붙여 넣지 않아도 돼요. 아래 [모델별 프롬프트 카드](#모델별-프롬프트-카드)를 보세요.

## 설치

터미널에서 Claude Code를 열고, 입력창에:

```
/plugin install prompt-enhancer --marketplace robinade/claude-mods-ko
```

처음 한 번은 `Add marketplace?`를 물어요. `y`를 누르고, 설치 범위는 맨 위의 `user`에서 Enter를 눌러요. 그 세션에서 바로 켜지고, 이후 여는 모든 세션에서도 켜져요.

- **업데이트**: `claude plugin marketplace update claude-mods-ko`를 실행한 다음 `claude plugin update prompt-enhancer@claude-mods-ko`를 실행하고, Claude Code를 다시 시작해요.
- **필요 조건**(Claude Code 2.1.295 이상, 모델 호출 비용, `CLAUDE_CODE_ATTRIBUTION_HEADER`)과 6종을 한 번에 설치하는 방법은 [mod 모음 README](../README.md)에 있어요.
- **설치 없이 한 세션만 써 보기**: 레포를 받은 뒤(`git clone https://github.com/robinade/claude-mods-ko`) `claude --plugin-dir claude-mods-ko/prompt-enhancer`로 실행해요.

## 사용법

- 입력창에 초안을 적고 `/enhance <초안>`을 입력하거나,
- 초안을 입력창에 적은 채로 프롬프트 위 밴드의 **다듬기** 버튼을 눌러요. 다시 쓴 프롬프트가 초안 자리에 들어가요.
- 다듬은 뒤에는 입력창에 포커스가 돌아와요. 고칠 게 있으면 고치고 Enter로 보내거나, 밴드의 **보내기** 버튼을 눌러요.

### 밴드 버튼 누르는 법 (한글 입력 상태 주의)

- 입력창에 포커스가 있을 때 `e`, `s`는 그냥 글자로 입력돼요.
- 밴드 단축키를 쓰려면 먼저 `ctrl+x tab`(또는 밴드 클릭)으로 밴드에 포커스를 옮긴 뒤 **영문 입력 상태**에서 `e`(다듬기), `s`(보내기)를 눌러요.
- **한글 입력 상태에서는 `e`, `s`가 `ㄷ`, `ㄴ`으로 들어가서 단축키가 먹지 않아요.** 한/영 전환이 귀찮으면 밴드에 포커스를 옮긴 뒤 `Tab`으로 버튼을 고르고 `Enter`를 누르거나, 버튼을 클릭하세요.
- `Esc`를 누르면 입력창으로 돌아가요.

### 긴 글을 붙여 넣었을 때

- 길게 붙여 넣으면 입력창에 `[Pasted text #1 +45 lines]`처럼 접혀 보여요. 원문은 Claude Code가 따로 들고 있다가 보낼 때만 펼쳐서, **밴드의 다듬기 버튼은 이 꼬리표 글자밖에 못 읽어요.** 그래서 이때는 다듬지 않고 방법을 안내해요.
- 긴 글은 `/enhance ` 뒤에 붙여 넣고 Enter를 누르세요. 명령으로 보내면 원문이 펼쳐져서 전달돼요.
- 또는 같은 글을 한 번 더 붙여 넣으면(입력창 아래 `paste again to expand` 안내) 입력창에 원문이 펼쳐져요. 그다음 다듬기 버튼을 눌러도 돼요.
- 5천 자 정도 초안은 다듬는 데 40초쯤 걸려요.

### 어떻게 모델을 부르나요

- 대화가 이미 있으면 **지금 대화를 이어서**(fork) 다듬어요. 프로젝트 맥락을 그대로 알고, 캐시를 써서 싸요.
- 새 세션이라 대화가 아직 없으면 **세션 모델을 따로 한 번** 불러요. 이때는 CLAUDE.md, AGENTS.md, 설치된 스킬 목록을 직접 읽어서 맥락으로 넘겨요.
  - 답의 최대 길이는 초안 길이에 맞춰 늘어나요(최소 8,192, 최대 16,000 토큰). 제한 시간은 4분이에요.
  - 이 한도에는 모델이 답하기 전에 속으로 생각하는 몫(thinking)도 들어가요. 지금 모델은 thinking을 끌 수 없어서, 짧은 초안도 최소 8,192로 넉넉히 잡아요. 예전 최소값 2,048은 생각에 한도를 거의 다 써서 답이 잘리거나 빈 답이 올 수 있었어요.
  - 답이 최대 길이에 걸려 중간에 잘리면, 잘린 글을 입력창에 넣지 않고 "초안을 나눠서 다듬어 주세요"라고 알려요.

### `429` 오류가 날 때

- **"모드의 모델 호출이 막혔어요(429)" + `CLAUDE_CODE_ATTRIBUTION_HEADER`가 보이면**: `~/.claude/settings.json`의 `env`에 `CLAUDE_CODE_ATTRIBUTION_HEADER: "0"`이 있다는 뜻이에요. 지우고 새 세션을 여세요.
  - 모드가 모델을 따로 부를 때는 Claude Code 머리말을 빼고 보내서, 이 값이 `0`이면 Claude Code 요청이라는 표시가 하나도 남지 않아요. 그러면 구독 로그인 요청이 429로 막혀요. 본 대화는 머리말이 있어서 멀쩡하기 때문에 원인을 찾기 어려워요.
  - 공식 문서: 이 값은 LLM 게이트웨이 캐시 호환용이고, Anthropic API에 직접 연결하면 캐시에 영향이 없어요. [System prompt attribution block](https://code.claude.com/docs/en/llm-gateway-protocol#system-prompt-attribution-block)
- **"사용량 제한(429)에 걸렸어요"만 보이면**: 진짜 사용량 제한이에요. 잠시 뒤 다시 해 보세요.

## 다듬기 규칙에서 눈여겨볼 두 가지

- **작업을 막는 것만 물어요.** 모호한 부분 중 작업을 막는 것만 Claude에게 묻게 하고, 나머지는 합리적인 가정으로 정해 진행하게 써요. 정한 가정은 밝히게 해요. (예전에는 "모호하면 확인을 요청하라"는 줄을 넣어서 Claude가 자주 멈췄어요.)
- **붙여 넣은 자료는 지우지 않아요.** 초안에 붙여 넣은 문서, 로그, 메일, 웹 글은 줄이거나 지우지 않고, 사용자 요청과 나눠 `<참고_자료>` 블록에 원문 그대로 둬요. 예외는 아래 카드가 빼라고 한 자료(모델 가이드 원문)뿐이에요.

## 모델별 프롬프트 카드

`cards/` 폴더에 모델마다 카드가 하나씩 있어요. 다듬을 때 세션 모델(`/model`이 보여 주는 이름)에 맞는 카드를 골라 다듬기 지시문 뒤에 붙여요.

- 지금 있는 카드: `cards/opus-5-5.md` — [Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5) 요약.
- **고르는 법**: 카드 첫머리의 `적용 모델:` 줄에 적힌 이름이 모델 이름에 통째로 들어 있으면 맞아요. 대소문자, `.`, `_`, 공백 차이는 무시해요.
  - `claude-opus-5-5[1m]`, `Opus 5.5 (1M context)`는 `opus-5-5` 카드에 맞아요.
  - `claude-opus-5-50`처럼 이름이 더 긴 모델이나, 별칭 `opus`만 보이는 경우는 맞지 않아요. 이때는 카드 없이 지금까지처럼 다듬어요.
- **해당할 때만 반영해요.** 카드 항목은 초안이 그 일일 때만 프롬프트에 들어가요. 짧은 초안에 군더더기가 붙지 않게 하려는 거예요.

  | 이런 초안이면 | 이렇게 써 줘요 | 메모 |
  |---|---|---|
  | 긴 작업 (여러 단계·파일·앱) | 할 일 목록, 끝까지 진행, 멈춰도 되는 때(답이 꼭 필요할 때, 지우기·배포·제출 직전) | `가이드: 할 일 목록·멈춤 조건` |
  | 화면 디자인 | 프로젝트 디자인 규칙부터 짚고, 피할 모양을 구체적으로 나열 | `가이드: 피할 디자인 명시` |
  | 스크린샷·차트·도표 | 필요하면 잘라 확대해 다시 확인한 뒤 답하기 | `가이드: 이미지 확대 확인` |
  | 여러 에이전트로 나누는 일 | 시간 예산 한 줄 | `가이드: 시간 예산` |
  | 붙여 넣은 자료 | 자료 안 지시는 요청 범위에서만 따르기, 무엇에 적용할지 명시 | `가이드: 참고 자료 구분` |
  | 붙여 넣은 자료가 이 가이드 원문 | 통째로 빼기(카드가 이미 반영) | `가이드: 가이드 원문 뺌` |
  | "신중히/단계별로 생각해" 같은 생각 지시 | 빼고, 필요하면 "결론과 근거를 짧게"로 | `가이드: 생각 지시 뺌` |
  | 메모리·콘솔·DB·메일 등 여러 곳 기록에 기대는 일 | 손대기 전에 관련 자료를 넓게 찾아 열어 보기 | `가이드: 먼저 넓게 살펴보기` |

- **카드에 넣지 않은 것**: effort, max_tokens, thinking display, 자동 이어가기처럼 API나 Claude Code 설정으로만 바꿀 수 있는 항목은 프롬프트로 다룰 수 없어서 넣지 않았어요.
- **새 모델 카드 더하기**: `cards/<이름>.md`를 만들고 첫머리에 `적용 모델: <이름>` 줄을 쓰면 돼요(여러 개면 쉼표로). 코드는 고치지 않아도 되고, 카드는 다듬을 때마다 새로 읽어서 `/reload-plugins`도 필요 없어요. 여러 카드가 맞으면 파일 이름 순으로 첫 카드를 써요.
- 카드를 읽지 못하면(폴더가 없거나 읽기 오류) 카드 없이 다듬어요.

## 무엇이 바뀌었는지

다시 쓰고 나면 밴드에 무엇을 더했는지 최대 3줄로 보여 줘요(참조한 파일, 적어 넣은 제약이나 '완료' 기준, 연결한 스킬 등). 카드 항목을 반영했으면 `가이드: 시간 예산`처럼 표시하고, 메모가 3줄을 넘으면 `가이드:` 메모를 먼저 보여 줘요. 각 메모는 한 줄이고 밴드 폭에 맞게 잘려요. 터미널에서 한글은 두 칸을 차지하므로 글자 수가 아니라 화면 폭 기준으로 잘라요. 메모는 보내거나 다시 다듬으면 사라져요.

## 취향을 배워요

다듬은 프롬프트를 보낼 때마다(`s` 또는 Enter) 보낸 내용과 다시 쓴 내용을 비교해서, 그대로 보냈는지 고쳐서 보냈는지 기억해요. 고쳐서 보낸 경우에는 두 버전을 각각 최대 300자까지 잘라서 보관해요(이모지나 한글 자모가 중간에 잘리지 않게 글자 단위로 잘라요). 다음 다듬기 때 이 기록을 참고해서, 매번 줄여서 보내면 더 짧게, 늘려서 보내면 더 자세히 써요.

- 같은 한글이라도 조합형(NFD)과 완성형(NFC)이 섞여 들어오면 다른 글자로 보일 수 있는데, 이 경우는 '그대로 보냄'으로 쳐요.
- 한국어는 영어보다 같은 내용을 적은 글자로 쓰기 때문에, 평균 25자 넘게 줄이거나 늘리면 취향으로 반영해요.
- 기록은 프로젝트(세션의 루트 폴더)별로 남기고, 최근 10번만 보관해요.
- 모드 전용 저장소(`$.store`, Claude Code 설정 폴더 아래의 JSON 파일)에 저장돼서 세션이 바뀌어도 이어져요.
- 다른 플러그인, 예약 작업, 다른 세션이 보낸 프롬프트는 기록하지 않아요.
