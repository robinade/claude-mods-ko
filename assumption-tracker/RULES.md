# assumption-tracker 규칙

## Claude가 받는 지시 (매 세션)

사용자는 한국어 사용자다. 작업하는 동안 사용자가 말하지 않은 것을 가정할 때마다 — 요구사항, 기본값, 라이브러리·도구 선택, 파일 위치, 데이터 형태, 모호한 표현의 해석 — `mcp__assumption-tracker__log_assumption`를 호출해 그 가정을 짧은 한국어 한 문장으로 기록하고, 계속 작업한다. 묻느라 멈추지 않는다. 가정은 그것을 세운 시점에 한 번만 기록한다. 사용자나 코드베이스가 이미 정해 둔 것은 기록하지 않는다. 파일 경로·명령·코드 식별자는 원문 그대로 쓴다.

사용자는 옆 패널에서 가정을 검토한다. 판정은 `[assumption-tracker]`로 시작하는 메시지로 온다. 틀렸다고 표시된 가정이 있으면, 그 가정에 기댄 작업을 곧바로 고친다. 정정 내용이 있으면 그대로 따른다.

## 키

| 어디서 | 키 | 하는 일 |
|---|---|---|
| 빈 입력창 | `0` | 패널 열기 (또는 `/assumptions`) |
| 패널 | `1` | 가장 최근 미확인 가정을 맞음으로 |
| 패널 | `2` | 가장 최근 미확인 가정을 틀림으로 |
| 패널 | `Tab` | 버튼과 정정 입력칸 사이 이동 |
| 정정 입력칸 | `Enter` | 틀림으로 표시하고 정정 보내기 |
| 패널 | `Esc` | 닫기 |

모든 단축키가 숫자라서 한글 입력 상태에서도 그대로 작동해요. 정정 입력칸에 커서가 있는 동안에는 입력한 글자가 모두 입력칸으로 가서, 숫자를 쳐도 단축키가 눌리지 않아요.

## 판정이 Claude에게 가는 방식

- Claude가 작업 중일 때: 다음에 Claude가 읽는 도구 결과에 붙어서 가요.
- Claude가 마지막 답을 쓰는 중일 때: 멈추지 않고 이어서 작업해 틀린 판정을 반영해요.
- Claude가 쉬고 있을 때: 틀림 판정은 새 턴을 시작해요. 맞음 판정은 기다렸다가 다음 메시지와 함께 가요.

판정 메시지는 이런 모양이에요.

```
[assumption-tracker] 사용자가 가정을 검토했어요:
- #2 "npm을 쓴다": 틀림. 사용자 정정: pnpm을 써요
- #3 "탭 대신 공백 두 칸": 맞음.
판정에 맞게 작업을 고치세요. 이 가정들은 다시 기록하지 마세요.
```

## 프로젝트 규칙 (매 세션, 작업 디렉터리별)

정정 내용이 있는 틀림 판정은 작업 디렉터리의 규칙으로 저장돼요. 정정 내용이 없으면 규칙이 생기지 않아요. 같은 가정을 다시 정정하면 그 규칙이 바뀌고, 맞음으로 표시하면 규칙이 지워져요. 프로젝트에 규칙이 있는 동안 Claude의 시스템 프롬프트에 이것도 들어가요.

```
# 정정된 가정에서 배운 프로젝트 규칙
이 프로젝트의 이전 작업에서 한국어 사용자가 아래 가정들을 정정했다. 각 규칙을 따르고, 원래 가정을 다시 하지 않는다.
- <정정 내용> (원래 가정: "<가정>")
```

패널은 `가정 <n>개 · 틀림 <n> · 규칙 <n>` 줄로 시작하고, 그 바로 아래 가정 목록보다 위에 규칙이 나와요. 규칙마다 `✗ 삭제` 버튼이 있어요(`Tab`으로 이동).
